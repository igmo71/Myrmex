# Myrmex

**Myrmex** — экспериментальный проект WMS / fulfillment-системы на платформе .NET.

Проект предназначен для отработки архитектуры, доменной модели и практических подходов к разработке складской системы: от базовой топологии склада до процессов приемки, размещения, хранения, отбора, отгрузки и аналитики.

Главная цель проекта — построить понятную, расширяемую и доменно-ориентированную архитектуру, которую можно постепенно развивать до уровня полноценной складской / fulfillment-платформы.

---

## Цели проекта

Основные цели Myrmex:

- смоделировать реальные складские процессы через явные доменные понятия;
- выработать устойчивую архитектуру для WMS / fulfillment-системы;
- использовать современные подходы .NET-разработки;
- проверить на практике сочетание Clean Architecture, DDD, Modular Monolith и vertical slices;
- минимизировать случайную сложность и избыточные абстракции;
- подготовить проект к эффективной разработке с помощью Spec Kit, Codex и других AI-инструментов;

---

## Предметная область

Проект посвящен складской логистике и fulfillment-процессам.

В фокусе находятся следующие области:

- структура склада;
- зоны склада;
- адресное хранение;
- складские ячейки / места хранения;
- номенклатура / SKU;
- единицы измерения;
- упаковки и уровни упаковки;
- LPN / handling units;
- приемка товаров;
- размещение;
- хранение;
- остатки и движения запасов;
- отбор;
- отгрузка;
- операционная аналитика.

Разработка ведется итерационно. Сначала стабилизируются базовые понятия, архитектурные правила и технические шаблоны, после чего функциональность расширяется по отдельным вертикальным срезам.

---

## Архитектурный подход

Myrmex строится как модульный монолит с доменно-ориентированной структурой.

В проекте используются следующие архитектурные идеи:

- Clean Architecture;
- Domain-Driven Design;
- Modular Monolith;
- vertical slices;
- Minimal API;
- Entity Framework Core;
- Aspire;
- явные команды и запросы;
- внутренний dispatcher вместо MediatR;
- разделение доменной логики, application-слоя, инфраструктуры и endpoints.

Проект намеренно избегает чрезмерно тяжелых фреймворков и универсальных абстракций там, где они не дают практической пользы.
